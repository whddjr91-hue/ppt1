# 기존 교수설계 시스템의 고급 도구 추가

이 문서는 기존 `AGENTS.md`, 모델 선호, 1~5세션 역할, 원고·완료본·세션 레지스트리를 유지한 상태에서 사용하는 추가 지침이다. 기존 `Initialize-Workspace.ps1`·`Fetch-SourceSkills.ps1`를 다시 실행하지 않는다. 고급 도구는 `advanced-tools.json`의 세션 매핑과 `advanced-tools.lock.json`의 고정 출처·파일 해시를 따른다.

## 세션별 적용

| 세션 | 추가·연계 도구 | 기존 기준 |
|---|---|---|
| 1 총괄 | MarkItDown 로컬 문서 전처리 | 사용자 판단·분배·최종 통합 유지 |
| 2 검수 | 기존 내장 PDF 스킬 + 공식 원본 보관 | 독립 검수·재검수 유지 |
| 3 제작 | PPTX Generator, PptxGenJS, Mermaid, MarkItDown | ppt-master 유지, 승인 프로토 우선 |
| 4 자료 | 기존 CLI 스킬 + OpenAI 고정 어댑터, 내장 PDF | 기존 code-first Playwright도 유지 |
| 5 디자인 | PPTX Generator, Mermaid 구조 설계 | 별도 사본에서 원본 디자인 보존 |

각 기존 역할 프롬프트 끝에 대응하는 `prompts/extensions/sessionN.md`를 읽는 안내만 추가한다. 원래 역할·본문·작업 순서는 유지한다. 현재 세션에 이미 동일한 PDF/Playwright CLI 기능이 있어 새 generic 자동등록은 하지 않는다. MiniMax 스킬만 새로운 `.agents/skills/pptx-generator`로 등록한다. 등록 링크와 실제 호스트 스킬 목록 갱신·실행 성공은 구분한다.

## 원본 양식과 외부 스킬이 충돌할 때

사용자 지시 → `AGENTS.md` → 승인한 원고·기관별 프로토 → 세션 추가 지침 → 외부 스킬 기본값 순서다. KEDI/KIRD의 실제 인치 크기·중앙 영상 영역·화면 설명·내레이션·자료란·글꼴·색·도형·싱크를 먼저 측정한다. MiniMax의 일반 발표형 표지/목차/배지, 10×5.625인치 기본값, Arial/YaHei, 새 팔레트는 기관 프로토에 강제하지 않는다. 외부 문서의 깨진 내부 앵커 2개는 원본을 고치지 않고 관련 reference 파일을 직접 읽는다.

PptxGenJS는 **기존 PPTX를 직접 import·편집하는 도구가 아니다.** 기존 템플릿을 편집할 때는 기존 ppt-master의 native 편집/XML 경로를 따른다. 새 객체 생성에는 프로토에서 얻은 규격·색·폰트·영역 좌표와 원본 경로·SHA256을 명시한 profile을 사용한다. 추가 엔진의 결과만으로 기존 템플릿의 마스터·애니메이션·구조가 그대로 보존됐다고 판단하지 않는다.

Mermaid는 학습 내용의 단계·관계 설계와 문법 검증에 쓴다. 현재 어댑터는 지원되는 flowchart 노드·관계를 추출해 프로토 색상·폰트·좌표에 맞춘 PPT 도형·텍스트·연결선으로 만든다. 기타 다이어그램 문법·지원하지 않는 노드/연결선은 거부하고 수동 구조 설계로 넘긴다. Mermaid SVG 전체를 최종 PPT 화면으로 굳히지 않는다. 별도 삽입 SVG 아이콘은 그림 객체이므로 개별 native 도형 편집과 구분한다.

## 문서 전처리와 한글 파일

MarkItDown 0.1.9는 PDF/PPTX/DOCX extras만 별도 가상환경에 설치한다. 오디오·Azure·OCR/LLM 유료 서비스나 전체 extras를 활성화하지 않는다. 어댑터는 로컬 파일만 `convert_local()`로 읽으며 원본 파일을 수정하지 않는다.

Linux/macOS 예시:

```bash
.local/advanced-documents-venv/bin/python tools/advanced-documents/convert_document.py /absolute/path/source.pptx --output /absolute/path/new-analysis.json
```

Windows의 Python 경로는 `.local/advanced-documents-venv/Scripts/python.exe`다. 전처리 결과는 내용을 분석하는 보조 자료이며 PPT 도형 구조·화면 배치·검수 메모·삭제표시·화자·화면/나레이션 구분을 보장하지 않는다. HWP/HWPX는 MarkItDown에 억지로 전달하지 않고 기존 한글 처리 경로로 반환한다. 이번 HWP/HWPX 테스트는 라우팅 가드 검증이며 실제 한글 파일 해석 검증이 아니다.

## 설치 상태 확인과 추가 도구만 설치

```bash
python scripts/Manage-AdvancedTools.py check
python scripts/Manage-AdvancedTools.py register
```

`check`는 고정 원본 해시와 문서/제작 모듈 import를 확인한다. 기존 계정·프로필·레지스트리·설정을 변경하지 않는다. `register`는 새로운 MiniMax 링크만 추가하거나 동일 등록을 유지하며 충돌하는 기존 경로를 덮어쓰지 않는다. PDF/CLI가 없는 다른 환경에서만 `--pdf-fallback` 또는 `--playwright-fallback`을 명시해 공식 원본을 등록한다.

추가 의존성이 없는 다른 컴퓨터에서만 다음 명령을 사용한다. 기존 프로젝트 전체를 설치하지 않는다.

```bash
python scripts/Manage-AdvancedTools.py install --documents
python scripts/Manage-AdvancedTools.py install --production
python scripts/Manage-AdvancedTools.py install --browser-cli
```

문서 환경은 `requirements.lock`의 버전·배포 해시로 설치한다. 제작 환경은 `tools/advanced-production/package-lock.json`에 고정된 패키지를 그 폴더에만 설치한다. 전역 npm/Python 업그레이드나 기존 초기화 도구 호출은 하지 않는다. 제작 도구는 Node 22.12 이상을 사용하며 기존 런타임을 임의로 업그레이드하지 않는다. 검수에는 현재 Poppler/LibreOffice/한국어 글꼴을 재사용한다.

`--browser-cli`는 먼저 기존 고정 버전 런타임을 확인하고 일치하면 추가 설치를 생략한다. 없는 환경에서만 `tools/advanced-browser/package-lock.json`의 CLI 패키지를 해당 폴더에 설치하며 브라우저 바이너리는 자동 다운로드하지 않는다.

```bash
node tools/advanced-production/scripts/diagnose.mjs
python tools/advanced-production/scripts/verify-diagnostics.py
.local/advanced-documents-venv/bin/python tools/advanced-documents/test_conversion.py .local/advanced-tests/documents
```

가상 KEDI/KIRD fixtures와 진단 산출물은 내부 검증 전용이다. 실제 기관 프로토·원고로 제작한 납품물이 아니며 기존 완성본의 품질·동일성을 검증하지 않는다. 실제 작업은 `tools/advanced-production/README.md`의 입력 profile·scene 규약을 따른다.

## Playwright 재사용 범위와 현재 제한

공식 원본은 `vendor/skills/openai-playwright/`에 고정 보관한다. 현재 기존 `playwright-cli`가 CLI·snapshot ref 기능을 포함하므로 새 generic skill 등록은 피하고, `tools/advanced-browser/playwright-cli.cjs`로 기존 Playwright 1.62.1의 버전·CLI 파일 해시를 확인해 사용한다. `npx @latest`나 두 번째 브라우저 패키지를 반복 설치하지 않는다. 기존 code-first playwright-skill은 삭제·변경하지 않는다.

```bash
node tools/advanced-browser/playwright-cli.cjs --runtime-info
node tools/advanced-browser/playwright-cli.cjs --help
node tools/advanced-browser/smoke.cjs --preflight
```

CLI 도움말·버전·snapshot/screenshot 명령 파서는 검증했지만, Chromium 공식 CDN 접근이 차단되어 실제 로컬 페이지 캡처 테스트는 미완료다. 공개 API preflight는 성공했으며 브라우저 실행은 `Browser chromium is not installed`로 실패했다. snapshot·screenshot 파일이 생성됐다고 보고하지 않는다. 기존 사용자 브라우저·로그인·인증정보를 연결하거나 사이트/브라우저 차단을 우회하지 않는다. 추후 정상적인 브라우저 다운로드가 가능한 환경에서 다음 명령으로 추가 바이너리만 설치·테스트할 수 있다. 이는 기존 작업환경 재설치가 아니다.

```bash
node tools/advanced-browser/playwright-cli.cjs --install-browser
node tools/advanced-browser/smoke.cjs
```

## 제작·검수 완료 기준

1. 입력 원고·프로토의 경로·SHA256과 승인 범위를 고정한다.
2. 핵심 관계를 도식·아이콘·인포그래픽으로 구조화하되 전체 승인 내레이션은 보존한다.
3. 싱크는 각 페이지 #1부터 시작하고 화면 변화와 동일한 순서로 매핑한다.
4. 도입·사례의 전체 화면은 승인한 프로토의 영상 영역 안에서 구성한다.
5. native 텍스트·도형·표·차트와 그림/SVG 객체의 편집 범위를 구분한다.
6. 모든 최종 페이지를 렌더해 가독성·줄바꿈·잘림·겹침·오탈자·출처를 실제로 확인한다.
7. 3 제작 → 2 검수 → 5 디자인 → 3 내용 확인 → 2 재검수 → 1 최종 통합을 유지한다.

원본 편집 앱 왕복·실제 녹음/모션 시간·미디어 사용권·기관 감수·사용자 최종 수용은 수행한 경우에만 완료로 기록한다.
