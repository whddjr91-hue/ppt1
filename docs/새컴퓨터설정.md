# 새 컴퓨터 설정

운영 문서 기준일: 2026-10-17. 기존 컴퓨터의 로그인·대화·실행 환경을 그대로 복제하는 절차가 아니다.

## 1. 저장소와 Codex

VS Code와 Codex 확장 `openai.chatgpt`를 설치하고 로그인한다. Git이 있으면 다음처럼 받거나 GitHub의 전체 ZIP을 사용한다.

```powershell
git clone https://github.com/whddjr91-hue/ppt1.git
code ./ppt1
```

프로젝트를 신뢰할 수 있는지 확인한 뒤 `.codex/config.toml`의 모델 선호가 실제 적용됐는지 Codex 설정에서 확인한다. 이 파일은 사용자 선호 `gpt-6.1-sol` / `high`를 지정한다. 계정에서 이용 가능한지, 별도 대화에서 무엇이 선택됐는지는 확인해야 한다. 한도·이용 가능 문제로 다른 모델로 임의 전환하지 않는다. 승인·샌드박스·조직 정책은 해당 컴퓨터의 정책을 유지한다.

공식 안내: [설정 예시](https://learn.chatgpt.com/docs/config-file/config-sample), [IDE 설정](https://learn.chatgpt.com/docs/ide/settings).

## 2. 경로와 스킬 초기화

저장소 루트에서 PowerShell을 연다.

```powershell
./scripts/Fetch-SourceSkills.ps1
./scripts/Initialize-Workspace.ps1 -CheckOnly
./scripts/Initialize-Workspace.ps1
```

첫 명령은 `source-lock.json`에 고정한 공개 원본 저장소의 스킬 5개를 `.local/skill-source/`에 내려받아 manifest 해시를 확인한다. 원본 라이선스도 함께 보존하며 패키지 설치나 스킬 실행은 하지 않는다. `Initialize`의 `CheckOnly`는 변경 없이 준비 상태를 확인한다. 마지막 명령은 원본 5개를 확인한 뒤 `.agents/skills/` junction과 `.local/session-registry.json`을 만든다. 기존 로컬 레지스트리는 보존한다. `.local`과 생성된 junction은 Git 추적에서 제외한다. 경로에 한글이나 공백이 있어도 저장소의 현재 위치를 기준으로 계산한다.

Codex CLI는 PATH 또는 현재 사용자 VS Code 확장 설치에서 탐색한다. 탐색 실패/잘못된 기존 선택이면 새 PC의 실제 실행 파일을 확인해 로컬 레지스트리 `codex_binary`를 수정한다. 원래 컴퓨터의 경로를 복사하지 않는다. CLI 도움말에서 `queue` 지원도 확인한다. 확장 버전에 따라 지원되지 않으면 명령을 추측하지 않는다.

실행 정책으로 PS1 로드가 차단되면 자동으로 정책을 변경하지 않는다. 오류를 총괄이나 환경 담당자에게 전달해 허용되는 실행 방법을 확인한다. Python/Node·패키지·브라우저·렌더러·한글/Office는 별도 의존성이며 [스킬 환경](스킬환경.md)을 따른다.

## 3. 역할을 가진 실제 세션 만들기

사용할 실제 VS Code 대화 1~5개를 만들고 `prompts/1세션_총괄.md`부터 역할에 맞는 시작 메시지를 보낸다. 세션 번호는 역할 이름이다. 실제 UUID를 각 대화에서 확인한 뒤 등록한다.

```powershell
./scripts/Register-Session.ps1 -Session 2 -ThreadId '<새 실제 2세션 UUID>'
./scripts/Test-SessionConnection.ps1 -Session 2 -PrepareOnly
```

`PrepareOnly`는 시험 문구와 challenge만 준비하며 실제로 보내지 않는다. 문구와 대상이 맞으면 실제 수신시험을 실행한다.

```powershell
./scripts/Test-SessionConnection.ps1 -Session 2
# 수신한 2세션이 지시된 .local/session-acks/...json을 작성한 뒤
./scripts/Confirm-SessionConnection.ps1 -Session 2
```

3·4·5도 같은 절차로 진행한다. 확인 명령은 같은 세션/UUID/nonce의 응답을 읽어야 `verified=true`로 바꾼다. 이는 수신 확인이며 암호학적 신원 인증이나 작업 완료가 아니다. 재등록하면 이전 수신시험은 무효다. 실제 세션에 다른 PC의 폴더가 자동 연결됐다고 가정하지 않는다.

## 4. 총괄에서 작업 지시

1세션이 UTF-8 메시지 파일을 준비하고 다음처럼 전송한다. 실제로 검증된 대상만 보통 작업을 받는다.

```powershell
./scripts/Send-SessionMessage.ps1 -Session 3 -MessageFile './.local/messages/task-for-session3.txt'
```

접수·실제 수신·산출물·독립 검수 상태를 나눠 관리한다. 과거 메시지를 모든 세션에 재전송하지 않는다. 구체적인 새 프로젝트가 지정되지 않았으면 제작을 시작하지 않는다. 원고와 참고 파일은 [프로젝트 이전 안내](프로젝트이전.md)에 따라 별도로 준비한다.
