## 세션별 실행

1은 범위·입력·프로토 대응·최종 파일을 확인한다. 2는 로컬 구조 검사 후 변경 범위의 의미/시각을 독립 검토한다. 3은 계획을 고정하고 원본 native 편집/객체 생성을 담당한다. 4는 신규 자료 또는 미해결 출처/권리 때만 실행한다. 5는 부분 수정의 구체적 디자인 결함과 신규 차시 대표/최종 검증에 실행한다. 같은 자료/정상 범위 재분석과 무수정 반환의 반복 렌더는 하지 않는다.

## 유지한 품질 기준과 미검증

심리 실제 프로토가 최우선이다. 같은 역할의 페이지·원형/말풍선/블릿/아이콘·위계·레이아웃을 의미에 맞춰 재사용한다. 원고·화자·조건·감수 메모·승인 나레이션·싱크·편집성·출처/권리·전체화면 사례·목표/내용/간지 양식 및 네 가지 실제 관측은 유지한다. 형식/개수/CRC 통과를 교육적 합격으로 바꾸지 않는다. 새 차시는 대표 화면의 실제 독립 교수설계·디자인 검증 전 양산하지 않는다. 구체적 결함만 수정하고 자동 수정 2회 후 남으면 보고하고 추가 실행을 기다린다.

기대 효과는 중복 모델 호출·전체 분석·전체 렌더 감소다. **실제 토큰/크레딧 로그가 없어 절감률과 비용 감소를 확정하지 않는다.** 이번에 확인한 것은 캐시 재사용·부분 영향 감지·필수 검수 유지·실행 차단이다. 같은 원고로 신규 2~3장을 재제작하는 비용 실험은 하지 않았다. 기존 3장 보완본의 사용자 디자인 수용도 미확인이다.

남은 위험: 상속 스타일의 최종 모습과 학습 의미는 실제 렌더 관측이 필요하다. HWP 취소선·메모는 기존 원본 확인을 거쳐야 한다. 외부 URL 내용/권리·렌더러/폰트 환경·의미상 연쇄 영향은 바이트 비교만으로 검증되지 않는다. 구조 비교가 지원하지 않는 OPC 문서 루트는 통과 대신 정밀 확인을 요구한다. 저수준 API나 임의 native 편집 스크립트까지 자동 통제하지 않으므로 동일 운영 계약을 적용한다. 기존 제작 job에는 execution 메타데이터를 추가한 사본이 필요하다. 다음 실제 제작에서 대표 페이지 품질과 기록 가능한 실제 사용량을 함께 확인해야 한다.
