# 작업 범위와 재사용 — 실행의 단일 기준

사용자 지시 → 실제 선택 프로토(디자인) / 승인 원고(사실·나레이션) → `prototype-policy.json` → 역할 지침 순이다. 아래 예외는 전체 제작의 독립 검수를 없애지 않는다. 기존 스킬·제작 엔진·원본·기존 작업물은 보존한다. 이 문서와 정책을 역할 프롬프트마다 다시 복사하지 않는다.

## 실행 범위

| 유형 | 실행 책임 | 필수 검사 |
|---|---|---|
| simple: 오탈자·비의미 윤문·싱크·좌표 | 담당/로컬 도구, 1 최종 확인 | 의미 불변 명시, 원본 검수 바인딩, 변경 비교·무결성·변경 페이지 실물 |
| partial: 페이지 제작·도식 등 의미/시각 구성 수정 | 3 제작 → 2 독립 검수 → 1 실물 확인 | 변경·의존 페이지의 원고·의미·시각·출처/싱크/편집성. 실제 디자인 결함이 있으면 5 별도 사본 →3 내용 확인 →2 재검수 |
| full: 신규 차시 전체·전체 최종 납품 | 3→2→5→3→2→1 | 독립 교수설계·디자인 검수, 대표 페이지 실물 채택, 전체 필수 양식·누락·출처 |

4는 신규 사진·영상·아이콘·권리 조사가 필요할 때 실행한다. 기존 권리 원장을 검증해 쓸 수 있으면 대기용 호출을 만들지 않는다. 역할 번호는 책임이며 실제 VS Code 대화 연결 또는 새 에이전트 실행을 뜻하지 않는다. 일반/전체에서 제작자와 독립 검수자를 같은 주체로 포장하지 않는다. simple에서 의미 변경이 의심되면 partial로 올린다.

전체 디자인 검사에서 결함이 없으면 변경 없이 채택한다. 5를 실행했다는 이유로 색·도형·레이아웃을 새로 만들지 않는다. 정상 페이지의 긴 보고서·전 페이지 재렌더를 역할마다 반복 생성하지 않는다. 한 개의 공유 근거 파일에 역할별 판정과 구체적 관측을 기록하고 입력/PPT/PNG 해시를 맞춘다.

## 로컬 계획과 모델

```bash
python tools/advanced-production/scripts/production-state.py plan \
  --task .local/task.json --catalog /actual/local/models_cache.json --output .local/plan.json
```

task의 필드: `task_type`, `semantic_change`, `changed_pages`, `dependent_pages`, `design_defects`(구체적 결함 목록), `new_assets`, `complex_judgment`.

같은 `gpt-6.1-sol`의 일반 판단은 medium, 복잡한 교수설계/과학·학술 판단은 high다. 문단 추출·형상 생성·좌표·폰트·누락·싱크·해시·렌더는 로컬 도구 우선이다. 4도 로컬 출처 정리부터 시작하며 기본 모델을 임의로 낮추지 않는다. 다른 저비용 모델은 해당 실행 환경에서 실제 지원·적합성과 사용자 허용을 확인한 경우에만 별도 선택한다.

계획 출력은 권고/인계 자료다. 실행기는 실제 지원하는 model/reasoning 인자를 새 호출에 전달하고 적용 결과를 별도로 기록해야 한다. 현재 UI 세션이나 다른 창의 모델이 바뀌었다고 주장하지 않는다. `.codex/config.toml`은 동일 모델의 기본 추론을 medium으로 두며 미확인 `default_subagent_*` 설정은 사용하지 않는다. 카탈로그 없이 실행한 계획은 `model_catalog_verified:false`다. 이 저장소는 백엔드의 과금표·현재 잔여 크레딧을 추정하지 않는다.

## 한 번 분석하고 바인딩

```bash
python tools/advanced-production/scripts/production-state.py analyze-prototype \
  /actual/prototype.pptx --output .local/prototype-measurements.json
```

실제 파일의 크기, 페이지별 native 객체·도형·텍스트/서체·색·블릿·연결선, 마스터/레이아웃 객체와 테마를 추출한다. 화면 밖의 상단 정보표·오른쪽 화면 구성/출처·노란 강사 지시·하단 흰 스크립트 영역도 확인한다. 고정 제작 지시를 임시 검토 메모로 오인해 삭제하지 않는다. theme/colorMap을 해석하지 않고 도형을 복사해 흰 박스가 검정으로 바뀌는 등의 오류는 실제 확장 렌더로 검출한다.

XML 추출은 서체 위계·아이콘 의미·학습성의 시각 분석 완료가 아니다. 첫 분석 때 실제 원본에서 도입 전체화면, 목표/내용, 본학습 도식, 사례 전체화면, 정리/확인학습 중 존재하는 역할을 선정해 원해상도로 읽는다. 없는 유형은 없다고 기록한다. 목표·간지·표/차트·도형/말풍선/블릿/아이콘·연결선·강사·제작정보 영역의 실제 스타일과 객체 ID를 보충한다.

프로필의 `prototype_role_samples`는 역할별 `[{page, render:{path,sha256,derived_from_sha256}, observation}]`이다. `derived_from_sha256`는 실제 선택 프로토의 SHA여야 한다. `Apply-PrototypePolicy.py bind`가 이를 보존한다. 페이지마다 같은 역할의 샘플과 native 객체를 선택한다. 장면 `visual.native_targets`는 node ID에서 실제 shape ID 배열로 연결한다. 실제 출력의 화면 영역/라벨과 승인 나레이션을 대조하며, 대본 상자를 화면 요소로 매핑해 통과시키지 않는다. 텍스트 없는 사진은 실제 pic ID와 `image_target_rationale`의 대상·행동 근거를 매핑하고 사람의 시각 검수를 받는다. 원·아이콘 개수, 텍스트 상자 분할, 자동 구조 검사는 시각적 의미의 대체물이 아니다. 특히 범례·직접 라벨, 대상의 단계별 색/형태 연속성, 조건과 판단이 읽혀야 한다.

승인 원고 구조/화자/나레이션/싱크, 역할별 프로필, 자산 출처·권리, 기존 검수/변경 이력은 아래 범용 캐시에 각각 저장한다.

```bash
python tools/advanced-production/scripts/production-state.py cache \
  --kind approved-narration --sources .local/inputs.json \
  --payload .local/approved-paragraphs.json --output .local/narration.json
```

`inputs.json`은 이름:실제경로 사전이며 원고·프로토·승인/감수 자료·관련 렌더 등 해당 분석에 영향을 주는 입력을 모두 포함한다. 캐시는 입력 바이트 해시+규칙/프롬프트/추출기 해시+분석 payload 해시로 구분한다. 불일치·파손이면 재계산한다. 승인/반려가 바뀌면 승인 payload도 바꾼다. 캐시 적중은 사람의 검수나 사용자 수용이 아니다. HWP 취소선·화자·양단 편집은 텍스트 추출만으로 확정하지 않는다.

원고 수정은 안정된 문단 `id`와 장면의 `paragraph_ids`, `depends_on_pages`를 사용한다. `diff-manuscript --before OLD.json --after NEW.json --scenes MAP.json --output DIFF.json`으로 수정·추가·삭제 문단과 전이 영향 페이지를 산출한다. 새 원고 해시로 바인딩하고 해당 구간과 공유 조건만 다시 읽는다. 미매핑 변경/신규 문단은 `unmapped_changed_paragraph_ids`로 반환하며, 매핑을 보완하기 전에는 부분 재사용을 차단한다. PDF 재흐름으로 달라진 줄 번호를 문단 ID로 간주하지 않는다.

## 실제 native 재사용과 부분 보존

`reuse-prototype.py --job JOB.json --output NEW.pptx`는 `{reference:{path,sha256},pages:[{source_page,text_replacements:[{shape_id,before,after}]}]}`를 받는다. 원본 페이지·도형·표·마스터·레이아웃·미디어 관계를 복제하며 지정 텍스트만 정확히 대조해 바꾼다. 원본/기존 출력은 덮어쓰지 않는다. 이는 새 장면의 의미 설계나 복잡한 도형 재배치를 자동 해결하는 엔진이 아니다. 그 작업에는 기존 ppt-master native 편집/OOXML 경로를 계속 사용한다.

`build.mjs`의 production 경로는 `templateReuse.pages`를 통해 이 도구를 호출한다. `prototypePolicy`의 binding/scenes 및 역할별 실제 샘플을 검증한다. 일반 색 띠/상자를 자동 생성하는 기존 `addScene`는 가상 진단 경로에서 계속 유지한다. 실무 양식을 그 기본 크롬으로 대체하지 않는다. PptxGenJS가 기존 PPTX를 import한다고 주장하지 않는다.

특정 페이지 수정은 원본 native 편집 경로에서 대상과 직접 영향 페이지만 바꾼다. `pptx-scope.py --before OLD.pptx --after NEW.pptx --pages 17`로 슬라이드 XML뿐 아니라 마스터·테마·이미지·차트·노트 등 공유 의존성의 변화도 검사한다. 공유 테마 변경으로 다른 페이지가 바뀌면 미지정 페이지 변경으로 차단한다. 전체 덱 재작성으로 이 검사를 우회하지 않는다. 한 장 발췌본은 `output_scope:excerpt`, 원래 `source_pages`를 명시하고 전체 덱 보존을 확인했다고 말하지 않는다.

guard review의 선택적 `operation:{path,sha256}`는 위 task 필드와 `original:{path,sha256}`, `baseline_review:{path,sha256}`, `output_scope`를 담은 파일을 바인딩한다. simple/partial은 원본·기준 프로토·기존 독립 검수/렌더의 해시와 유효한 페이지 범위·구체적 관측을 재확인한다. 전체 덱 부분 수정은 재사용할 나머지 페이지의 기존2·1 검수 범위가 있어야 한다. 누락된 기준 근거를 자동 PASS로 채우지 않는다. `changed_pages + dependent_pages`와 실제 검수 페이지가 같아야 한다. 전체 덱이면 scope 비교도 통과해야 한다. operation을 주지 않은 기존 검수는 전체 순서의 엄격한 기본값을 유지한다.

## 대표 페이지 → 양산

`prototypePolicy.stage:pilot`은 1–3쪽만 허용한다. 먼저 대응 프로토와 구성 계획을 확정하고 실제 렌더의 내용·의미·시각·자료/싱크/편집성을 직접 판정한다. 전체 양산(stage:production)은 해시가 고정된 `prototypePolicy.pilot.scenes`와 `pilot.review`를 요구한다. review에 현 원고의 `manuscript_sha256`를 넣는다. 대표 계획은 현재 전체 계획의 실제 부분집합이어야 하며 전체에 case/diagram이 있으면 해당 유형을 대표 검사에 포함한다. 원고·프로토·계획·렌더가 바뀌었으면 이전 대표 PASS로 통과시키지 않는다.

문법·CRC·도형 수·자동 계약은 이 검수의 대체물이 아니다. 실물 결함이 있으면 반려하고 구체적인 결함 ID로만 수정한다. `production-state.py correction --state STATE.json --defect ID --artifact INPUT.pptx`는 작업당 자동 수정 2회 이후 추가 실행을 거부한다. 호출기는 성공 시 accepted 상태를 고정하고 새 사용자 지시가 없으면 재실행하지 않는다. 미해결이면 원인·변경 범위를 사용자에게 보고한 뒤 추가 실행을 진행한다. 이 로컬 기록은 외부 호출기를 강제로 중지하는 전역 스케줄러가 아니다.

## 검증·측정과 완료

동일 해시의 정상 근거는 공유하고 변경·의존 페이지만 재렌더한다. 새로 렌더해야 하는 최종 페이지를 캐시로 꾸며 내지 않는다. 수정이 없으면 검수 목적의 추가 PPT 사본·긴 보고서를 반복 만들지 않는다. 최종 무결성/필수 native 편집성 검사는 유지한다.

`usage --event EVENT.json --log LOG.jsonl`에 실제 호출 수·수정/결함 수·로컬 시간·캐시 적중을 기록한다. provider 사용량 로그가 없으면 `actual_usage:null`을 유지한다. 실제 토큰/크레딧 수치를 넣으려면 `usage_evidence:{path,sha256}`가 필요하다. 역할 단계 감소를 실제 과금 절감률로 바꾸지 않는다. 비교할 과거 로그가 없으면 정적 원인과 로컬 재사용/보존 시험 결과만 보고한다. 대규모 양산·반복 이미지 생성·과금 실험은 실행하지 않는다.
