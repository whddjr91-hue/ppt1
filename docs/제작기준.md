# 제작 기준

## 시작 인터뷰

사용자가 프로젝트의 주제와 대상 등을 대략 지정한다. 총괄은 주제·대상·학습 목적부터 확인하고 다음 항목을 단계적으로 구체화한다. 한 번에 관련 질문 2~3개 이하로 묻고 이미 받은 답변은 다시 묻지 않는다.

- 원고·감수 의견·제공 자료와 신규 집필 범위
- KEDI/KIRD 중 기준 양식과 정확한 참고 파일
- 목표 길이·편수·화면 비율·촬영/성우/강사 혼합 방식
- 내레이션·자막·싱크·화면/촬영/그래픽/음향 지시 범위
- 산출물·일정·권리·검수 조건

확정값, 제안, 가정을 분리한다. 원고나 사용자가 특정하지 않은 프로젝트를 임의로 시작하지 않는다.

## 양식과 원고

선택한 PPT를 실제 화면으로 분석한다. KEDI/KIRD 모두 16:9여도 슬라이드의 인치 규격은 다를 수 있으므로 원본의 실제 크기를 보존한다. 중앙 영상 시안, 주변 제작 정보, 내레이션, 자료/싱크란의 위치와 표·도형·색·글꼴을 따른다. 다른 참고 PPT는 보조로 명시한다.

원고의 활성 본문, 감수 메모, 취소선, 후속 의견을 구분한다. 원고 보존 원칙과 사용자 승인 예외를 함께 기록한다. 문단→장면→내레이션/화자→화면 핵심어→싱크/제작 지시→출처를 추적할 수 있어야 한다. 사례의 조건·행위 주체·비판 귀속·판정 유보를 화면 축약 과정에서 빼지 않는다.

## 사례와 시각 자료

프로젝트에 합의된 경우 소주제 첫 사례·조건부 상황은 중앙 영상 영역 전체 이미지/영상으로 구성한다. 일반 활용 설명을 새 실제 사건으로 만들거나 원래 강사 음성을 성우로 임의 변경하지 않는다. 정리하기는 합의된 마지막 페이지에 두고 기존 낭독문과 순서를 보존한다.

자료에는 제공처·개별 URL·ID·작가 확인 범위·확인일·사용권 상태를 남긴다. 생성/자체 제작 자료는 도구·제작일·프롬프트나 제작 코드·승인 기록을 연결한다. 일반 스톡/설명용 재현과 실제 사건 증거를 구분한다. 영상 정지컷이면 정지컷·MP4 확보/삽입/전체 재생 여부를 각각 기록한다.

공개 미리보기를 최종 사용권이 있는 자료로 취급하지 않는다. 워터마크 유지, 접근 차단/미확보, 실제 원본 정보량과 캡처 확대 해상도를 구분한다. 승인된 선별/삽입 범위의 작업은 진행하고 새로운 연출이나 중요한 범위 변경만 총괄이 사용자에게 묻는다.

세부 프로젝트값은 `templates/project.json`으로 시작하고 `프로젝트설정/`의 예시를 참고한다. 원고·참고 파일은 별도로 준비한다.


## 필수 프로토 설계 정책

`../prototype-policy.json`과 `../.claude/skills/storyboard-prototype/SKILL.md`를 적용한다. 동일 역할의 실제 프로토와 원고를 대조하고 대상·행동·관계·조건·판단이 읽히는지 별도 판정한다. 원고 보존/형식·무결성 검사는 교수설계 통과가 아니다. 등록·바인딩은 `python scripts/Apply-PrototypePolicy.py --help`, 계획/검수 계약은 스킬의 prototype_guard.py를 쓴다. 외부 기본 디자인을 프로토에 강제하지 않는다.

## 분석 재사용과 부분 수정

실제 프로토의 역할별 페이지·폰트·색·여백·객체·강사/사례/학습목표/스크립트 영역을 실제 렌더와 함께 기록한다. 도입·목표/내용·도식·사례·확인학습 등 대표 역할은 실제 존재하는 페이지로만 매핑한다. 파일·분석 규칙의 해시가 일치할 때만 분석 결과를 재사용하며, 파일이 없거나 변경되면 다시 확인한다. 검수 기록은 작업 산출물의 해시까지 일치해야 재사용할 수 있다. 캐시는 직접 관측을 대신하지 않으며 교육적 합격을 자동으로 만들지 않는다.

수동 캐시 도구 `python scripts/analysis_cache.py`의 `put`/`get`에 원고·프로토·결과물 등 관련 파일을 `--input`으로, 정책과 분석 스크립트·버전 명세를 `--rule`로 각각 빠짐없이 반복 지정한다. 입력 중 하나가 바뀌면 미스다. 기본 저장 위치는 제공하지 않으므로 `.local/analysis-cache` 등 비공개 폴더를 명시한다. 현재 도구는 캐시만 제공하며 자동 문단 변경 감지나 파이프라인 연결을 수행하지 않는다. 단순 구조 비교는 `python scripts/compare_pptx.py 이전.pptx 이후.pptx`를 사용할 수 있다. 공유 파일 변화는 전체 의존성 재검토로 취급하며 출력의 번호는 페이지 순서가 아닌 PPT 내부 부품 번호다.

특정 페이지 수정은 원본 사본의 요청 페이지와 직접 영향을 받는 범위만 수정한다. 변경 전후 슬라이드와 공유 마스터·레이아웃·미디어 등 의존성 차이를 점검하고, 의도하지 않은 변경이 있으면 재검토한다. 변경 페이지의 실제 화면, 원고·싱크, 프로토 대응 및 영향 범위를 확인한다. 전체 재제작은 사용자가 명시한 경우에만 한다. 대표 페이지를 먼저 검토하고, 동일 결함 자동 수정은 기본 2회 이내로 제한한다.
