# 검수와 근거 보고서

## PPT 검수

- 원고·학습목표·감수 의견 처리 연결, 화자·조건·문장 순서·장면 순서·마지막 정리
- 장면별 시작/종료/지속시간과 합계, 추정/실측 구분
- 실제 기준 양식·크기·글꼴·표·도형·싱크·제작 지시 위치
- 오탈자·누락·예시 문구 잔존·페이지/상자 밖 글자·잘림·겹침·단어 분리
- 실제 PPT 구조·관계·미디어·편집 가능성, 같은 버전의 PDF/PNG 출력
- 실제 사용 자료와 장면 ID·개별 출처·자료란·원본/삽입 해시 일치

검수 방법과 범위를 기록한다. 전체 연락판 검토와 모든 원해상도 페이지 열람, 구조 검사와 PowerPoint에서의 열기·편집·재저장은 각각 다른 검수다. 렌더 생성만으로 시각 검수 통과라고 하지 않는다. 글꼴의 등록·임베딩 바이트·실제 출력 글리프·앱 동작도 구분한다.

미사용 상속 바이너리를 실제 사용 자료 수에 더하지 않는다. 과거 후보·기각 연결과 현행 출처를 분리한다. 문서의 메모 처리 경로 수와 장면에 직접 표시된 메모 ID 수를 혼동하지 않는다.

## HWPX 보고서

기본은 한글에서 편집할 수 있는 HWPX다. 사용자가 다른 형식을 지정하면 따른다. 제공 개요, 원고·양식·근거 요약, 장면과 자료의 연결, 자산별 출처·확인일·권리 상태, 반영/보류·미확인 사항을 담는다. 실제 사용 자료만 현행 목록에 넣고 원문 주장·외부 근거·창작 제안을 구분한다.

구조와 본문을 확인하고, 가능하면 실제 앱에서 연다. DOCX를 함께 제공한다면 HWPX와 본문을 맞추고, PDF에서 문장 순서·긴 URL·클릭 대상·쪽 밖 문자와 실제 페이지 배치를 확인한다. DOCX에서 만든 PDF를 HWPX의 한글 앱 렌더로 표현하지 않는다. 기술적 해시 상세는 연결 원장으로 두고 본문은 읽기 쉬운 출처·근거 요약으로 작성한다.

## 최종 제공

1이 같은 PPT·PDF·장면 JSON·최종 검수 판정을 연결해 별도 제공 사본을 채택한다. PPTX/HWPX/DOCX는 확장자만 바꾸지 않고 파일 구조를 확인한다. 자료 묶음은 포함 목록을 고정한 뒤 재개봉 CRC·전파일 SHA와 디스크 원본을 대조한다. 독립 폰트·내부 런타임·인증·진단 파일을 무심코 묶지 않는다. 내부 PASS를 최종 공개 권리 취득·기관 공식 감수·사용자 디자인 수용으로 확대하지 않는다.
