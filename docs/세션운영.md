# 1~5세션 운영

| 세션 | 담당 | 편집 범위 |
|---|---|---|
| 1 | 총괄·사용자 인터뷰·배분·승인·통합 보고 | 공통 확정 기준·최종 제공 사본·근거 보고서/자료 묶음 |
| 2 | 독립 검수·수정 지시·재검수 | 담당 검수 기록. 제작 원본을 직접 고치지 않음 |
| 3 | 원고·장면·PPT 제작, 디자인 반환의 내용 확인 | 제작 전용 폴더와 코드 |
| 4 | 매체·글꼴·출처·권리 | 자료 전용 폴더와 자산 원장 |
| 5 | 디자인·글꼴·레이아웃·가독성 | 3의 고정 입력을 복사한 디자인 전용 폴더 |

## 작업 규모별 실행

- 단순 오탈자·싱크·좌표 수정은 담당 또는 로컬 도구가 수행하고, 변경 페이지와 직접 영향 범위 및 파일 무결성을 확인한다. 최종 납품 전체 차시 검수로 확대하지 않는다.
- 일반 페이지 제작·부분 수정은 3이 제작하고 2가 변경과 직접 영향을 독립 검수한다. 디자인 결함이 있을 때만 5, 신규 자료가 필요할 때만 4를 호출한다. 1은 실제 파일과 근거를 확인한다.
- 신규 차시 전체 제작 및 최종 납품은 아래 전체 순서와 같은 산출물에 대한 2·1의 독립 의미/시각 검수 기록을 유지한다. 기존 분석과 검수는 입력·규칙·산출물 해시가 모두 맞을 때만 재사용한다.
- 각 역할은 기존 연결을 재사용한다. 세션의 생성·수신·활성화 여부는 실제 도구로 확인하고, 불필요한 새 담당을 만들지 않는다.
- 결함이 구체적으로 확인된 경우에만 수정하며 자동 수정은 기본 2회까지다. 이후 문제가 남으면 원인과 실제 결과를 총괄이 사용자에게 보고하고 추가 실행을 기다린다. 미해결 결함은 최종 PASS가 아니다.

## 신규 차시 전체 제작과 최종 납품 순서

1. 총괄이 작업 ID, 사용자 답변, 기준 파일, 소유 경로, 완료 조건을 정한다.
2. 4는 신규 자료·미해결 출처/권리가 있을 때 조사하고, 3은 제작하며, 2·5는 필요한 기준을 사전 검토한다. 독립 파일에서만 병행한다.
3. 2가 3 제작본을 검수한다. 오류는 소유 담당에 수정 요청하고 재검수한다.
4. 5가 고정한 제작본의 별도 사본에서 디자인을 보완한다.
5. 3이 반환본의 원고·조건·화자·순서·시간·구조를 확인한다.
6. 2가 같은 개선본 해시의 실제 화면·출처·구조를 독립 재검수한다.
7. 1이 담당 보고와 실제 파일을 확인하고 PPT·한글 보고서·자료 묶음을 통합한다.

디자인 담당이 해결할 항목만 남았다면 2는 입력 해시와 잔여 결함을 명시해 ‘디자인 인계 가능·최종합격 아님’으로 넘길 수 있다. 이 상태를 최종 PASS로 확대하지 않는다. 3 확인과 2의 독립 검토는 읽기 전용으로 병행할 수 있으나 최종 판정 전에 필요한 확인이 모두 있어야 한다.

## 지시와 보고

`templates/인계보고.md`를 사용한다. 입력별 버전/해시, 완료 범위, 실제 근거, 결함과 해결 ID, 미확인 사항을 구분한다. 같은 파일의 여러 해시를 한 판정처럼 섞지 않는다. 정상 부분의 검증 근거는 이어 쓰고 변경·연쇄 영향에 집중한다.

담당은 사용자에게 직접 질문하지 않고 이유와 선택지를 1에 보고한다. 2는 총괄이 정한 소유와 승인 범위 안에서 3·4·5에 최소 수정 요청을 할 수 있다. 소유 충돌·새 아이디어·중요 범위 변경은 1이 조정한다. 알려진 결함과 필수 조건이 해결되면 종료하고 새 지시를 기다린다.

## 새 컴퓨터의 실제 연결

VS Code 별도 대화와 내부 보조 에이전트는 다른 실행 주체다. 세션 번호는 역할이며 UUID 자체가 아니다. 실제 대화를 열어 UUID를 확인하고 로컬 등록·수신 시험을 한다. 이전 컴퓨터의 UUID·ack·verified 값을 복사해 연결을 주장하지 않는다.

공식 CLI에 `queue`가 있는지 해당 설치본의 도움말로 확인한다. 지원되지 않으면 명령을 추측하지 말고 대화 연결 수단을 다시 확인한다. 전송 접수는 수신·작업 완료가 아니다. 타임아웃 뒤 상태 확인 없이 같은 지시를 중복 발송하지 않는다. 로그인과 조직의 승인·샌드박스/실행 정책을 임의 변경하지 않는다.


## 실행 계획과 모델 적용

작업 시작 시 `python scripts/production_plan.py .local/job.json`으로 정책의 단일 실행 표를 읽는다. job의 kind는 simple/partial/full, pages는 실제 표시 페이지 번호다. simple의 change_type은 typo/sync_number/coordinate만 허용하며 문장 의미·나레이션·도식 재설계는 partial이다. 디자인 결함은 design_defects에 구체적으로, 신규 자산은 new_assets에 기록한다. 실행 계획은 에이전트를 자동 생성하지 않으며 1이 기존 담당에 필요한 페이지·구절·프로토 대응·변경점만 전달한다. 작업 유형/영향 범위를 축소해서 필수 검수를 피하지 않는다.

| 담당 | 기본 실행 | 상위 추론 조건 |
|---|---|---|
|1|일반 배분 medium|복잡한 교수설계·최종 품질 판단 high|
|2|구조/싱크/누락 코드, 내용/시각 medium|학술 오류·복잡한 교수설계 high|
|3|객체 생성 로컬, 일반 설계 medium|복잡한 구조화 high|
|4|검색/기존 원장 도구 우선, 필요시 같은 모델 medium|학술 적절성 high|
|5|좌표·정렬 코드 우선, 의미/시각 medium|복잡한 구조 판단 high|

같은 gpt-6.1-sol 모델을 유지하고 지원되는 medium/high만 요청한다. 현재 호스트의 역할 도구에는 이 모델과 수준이 노출되어 있으나, 다른 컴퓨터의 CLI 또는 기존 별도 대화에 적용됐다는 뜻은 아니다. 지원/적용 확인이 안 되면 현재 모델을 보존하고 미검증으로 보고한다. 기본 설정만으로 세션별 동적 라우팅이 자동 적용된다고 주장하지 않는다. 한도 소진 시 성능을 임의로 낮추지 않는다.

신규 차시는 phase=pilot에서 2~5쪽의 대표 화면을 먼저 고정한다. full의 phase 누락·오타는 실행 거부한다. phase=bulk 실행에는 pilot 검수 파일의 SHA, 원고/프로토/규칙 SHA, 실제 결과물과 렌더 SHA, 각 페이지의 2·5 독립 관측, 대표 유형 대응 또는 해당 없음의 근거를 요구한다. 자동 검사는 기록 연결만 검사한다. 실제 화면 품질 판단을 대신하지 않는다. 사용자 반려/잔여 결함이 있으면 양산하지 않는다.

partial의 prototype_guard review 기록에는 task.kind=partial, task.pages, before_artifact 경로/SHA를 넣는다. 장면·검수 페이지는 요청 및 영향 범위와 같아야 하고, 실제 변경/의존성 영향 페이지 누락이면 실패한다. role2와 role1의 네 판정·실제 렌더 관측은 유지한다. 5가 수정하면 3 내용 확인과 2 재검수를 반드시 거친다. simple 결과는 기계적 범위 검사일 뿐 의미 품질/전체 납품 통과로 보고하지 않는다. 무나레이션 양식 페이지도 시각 검수 대상에서 빼지 않는다. guard의 silent 예외는 원고 삭제 통로가 아니며, 실제 사용자 승인에 연결된 approved_change_id가 바인딩에 있어야 한다.

설정 키는 공식 OpenAI Codex `codex-rs/core/config.schema.json`(2026-10-28 조회, blob f11dfba29c7b44ca7f87c3a01e7407d2bf4a9111)의 model_reasoning_effort와 agents.default_subagent_model/default_subagent_reasoning_effort에 존재함을 확인했다. 이 환경에는 Codex CLI가 없어 로컬 CLI 적용 검증은 수행하지 못했다. 현재 호스트 역할 도구의 모델·추론 지원과 CLI 설치본의 지원을 구분한다.
