# 역할과 검수

| 역할 | 필수 작업 |
|---|---|
| 1 총괄 | 프로토/원고 경로·SHA·기관을 고정한다. 원고→장면→프로토 페이지 대응을 읽는다. 최종 파일과 변경 페이지를 직접 본다. |
| 2 검수 | 원고 보존 외에 화면의 대상·관계·조건·판단을 검사한다. 프로토와 나란히 보고 구체적 학습/시각 결함을 반려·재검수한다. |
| 3 제작 | 사례·설명·도식·강조·퀴즈·정리를 구분한다. 의미 항목·싱크/요소 대응을 작성한 뒤 native 화면을 만든다. |
| 4 자료 | 상황/행동에 맞는 실제 영상·이미지 미리보기를 확보한다. 요청된 MotionElements 영상 후보를 우선 검토한다. 기사/논문은 근거 보조로 쓰고 제공처·ID·권리·SHA를 맞춘다. |
| 5 디자인 | 고정 제작본의 별도 사본에서 프로토의 서체·위계·강사 위치·도식 관계를 보완한다. 의미 없는 아이콘·원을 추가해서 해결하지 않는다. |

## 네 가지 독립 판정
1. 원고·사실: 화자, 수치/단위, 조건/가능성/귀속/부정이 유지되는가?
2. 학습 의미: 대상과 행위·비교/원인결과/분류/조건·핵심 판단이 읽히는가? 결론이 없는 사례 도입은 역할이 분명한가?
3. 프로토·시각: 같은 역할의 프로토 페이지와 실제 비교했는가? 서체·위계·배치·영역·가독성·잘림·겹침이 맞는가?
4. 자료·싱크·편집성: 실그림과 출처가 맞는가? 구절과 요소가 대응하는가? native 편집 범위와 영상 취득/재생 여부를 정확히 보고하는가?

각 판정에 페이지별 관측 근거를 쓴다. ‘스킬 적용/아이콘 있음/원고1440자 일치/겹침0’만으로 학습 의미를 통과시키지 않는다.

## 인계
전체 제작은3→2→5→3→2→1을 지킨다. 단순/부분 수정은 저장소의 단일 운영 기준 `prototype-policy.json` / `docs/작업범위와재사용.md`를 적용한다. 역할 책임은 유지하며 실제 필요한 역할만 호출한다. 4는 신규 자료가 있을 때 지원한다. 기존1~5 역할을 재사용하고 새 이름을 누적하지 않는다. 실제 VS Code/다른 대화의 연결은 확인한 경우만 기록한다.

검수는 같은 PPT SHA와 PNG 경로·SHA, 비교 프로토 페이지, 네 판정과 관측 문장, 역할·시각에 묶는다. 일반/전체 제작은 역할2 독립 검수와 역할1 직접 확인이 없으면 채택하지 않는다. 비의미 단순 수정은 원본 검수 바인딩·변경 범위·로컬 검사·역할1 직접 확인을 요구하며 의미 변경이면 일반/전체로 올린다. 사용자 수용·기관 감수·이용허락·PowerPoint 앱 확인은 내부 PASS와 별개다.
